# ArkTerminal · Prompt 10：性能、稳定性与最终验收

版本：2026-10-30 · 原始十阶段增强版

使用方式：将本文件全文交给实施 Agent，并明确要求执行本阶段。本文件已包含必要约束与验收，可独立作为阶段 Prompt；运行依赖仍需前序阶段提供。当前交付内容是规划文档。

## 一、任务梗概

完成基于测量的优化、全链路回归和首版发布收尾。交付 MSIX 安装包与便携 ZIP，验证真实安装/解压后的行为；首版范围内缺陷不以“后续再做”代替。

## 二、前置条件与任务范围

**前置条件：**阶段 1—9 的真实功能已完成并可构建；阶段 2/3 关键质量验收通过。具备 Windows Release/打包工具链与可验证环境，签名条件如实记录。

**本阶段包含：**性能基线、异常矩阵、资源/隐私/协议回归、Debug/Release 构建、双格式打包、手动升级与实际运行验证、必要使用说明。

**阶段边界：**本阶段不扩张功能；后续工作区、多窗口、分屏、插件、广播、MCP 写入等按后续清单保留，不算首版缺陷，也不在此阶段偷偷实现。

## 三、必须遵守的工程约束

你是 ArkTerminal 的实施 Agent。收到本文件及明确的实施指令后，只执行本阶段；本文件本身不代表用户已要求开始编写应用。

以下是贯穿首版的最终约束；尚未轮到的功能按本阶段范围预留，不提前扩张实现。

- 产品是 Shell 与 Agent 并重的 Windows 10/11 x64 原生 WPF 工作台。保留 `net10.0-windows`、ConPTY 和原生渲染路线；不使用 WebView2/xterm.js，不引入大型 UI 框架。最低 Windows 构建号须以实际依赖和能力验证为准。
- 先读仓库 `AGENTS.md`、解决方案、相关源码和已有阶段交接。原材料描述仓库接近空白，实施时重新核实，保留用户已有改动和稳定公共契约。不要仅因文件名不同就复制一套同职能服务。
- 每个 Session 独立拥有进程、I/O、缓冲和取消源；View 负责显示与输入。UI 线程不做扫描、进程探测、输出解析或阻塞 I/O；队列、缓存、日志、回滚均有上限和释放路径。
- 首版同时支持标准数据目录与便携模式；所有文件访问经统一数据根服务，配置原子写入。标准/MSIX/便携模式的数据默认隔离，不静默迁移或降级覆盖高版本配置。
- 正常启动显示新建页，由用户选择项目或 Agent；崩溃恢复只恢复待确认配置草稿和未启动布局。专注模式保留标签栏。完整工作区、多窗口、分屏和 Quake 在后续版本实现。
- 不自动运行检测到的 Agent，不修改用户 Agent 全局配置，不收集遥测或自动上传正文。应用命令历史和按会话输出保存默认关闭；MCP 首版只读。模型建议的生成、投递与实际执行分别处理。
- 新增依赖先检查替代能力，记录具体包名、固定版本、用途和许可证。项目没有测试基础设施时，不擅自新建测试项目、报告目录或脚手架；已有相关测试可运行，必要应用内诊断应服务真实产品功能。
- 应用始终手动更新，不做云同步、账号、插件商店或主题商店；本地插件/主题导入属于后续版本。不自动 commit、push 或对外发布；本阶段必要的本地构建和文档更新在范围内。

文中的默认上限与时长是实施建议，不是用户逐项指定的硬指标。实现为集中可调整配置；如需调整，在交付中说明原因和实际值，不能悄悄放宽用户已确认的权限与数据边界。

## 四、任务要求

### 测量、稳定性与缺陷修复

1. 使用 Release 记录冷启动到新建页、创建会话、标签切换、连续输出、20 标签、后台输出、极光活动/关闭和性能模式的基线。记录机器/OS/DPI/字体与样本条件，不凭空规定已达固定毫秒/内存目标。
2. 检查有界回滚/字节预算、队列背压、缓存、可见行重绘、后台暂停、设备丢失恢复与失焦降帧；不要为变快丢输出字节或跳过终端状态更新。
3. 对循环创建/关闭会话、全局热键、IME 切换、失败启动、UAC 取消、磁盘满、坏配置/草稿/图片/适配器、远程/多 DPI 显示做失败矩阵。检查任务、句柄、进程树与共享图形资源的增长/释放。
4. 检查正常启动新建页，崩溃恢复不自动启动，专注模式保留标签，Shell 关闭或 Agent 不可靠时状态降级，通知只在失焦时发送。
5. 检查默认无命令历史/输出转录，开启后有限且可清理；正文不混入诊断，MCP 只读且有披露授权，跨 Agent 预览取消无传递。脱敏用合成秘密样例验证，不使用真实凭据。
6. 运行 Debug 与 Release 的 dotnet build ArkTerminal.sln，执行本文件的完整验收矩阵；未通过或未验证的高优先级项目逐项列出，不用“基本完成”替代。
7. 清理实验后端、无用依赖与临时诊断代码；保留产品性能面板、脱敏导出和必要打包资产。随后执行本阶段的双格式打包任务。

### MSIX / 便携 ZIP 打包

1. 先核实 Windows/.NET/SDK 与包模型，确定并记录最低 Windows 构建号、x64、运行时依赖。ZIP 默认采用 self-contained win-x64，除非现有明确约束要求 framework-dependent；无额外需求不启用 trimming/AOT 或单文件以免破坏 WPF/互操作。
2. ZIP 包含 ArkTerminal、必要依赖、MCP/提权辅助器与 portable.flag，配置和资源在 data/。换到路径含中文/空格的可写目录可用，不依赖原开发机路径；目录只读/磁盘满有明确错误，不静默回退 APPDATA。
3. MSIX 包使用符合所选模型的清单、权限与可写用户数据目录，不写安装目录，核实重定向/卸载行为。验证原生 DLL、ConPTY、全局热键、通知、MCP 入口及管理员辅助器均可运行；在包身份下重新测试，不能沿用 ZIP 成功结论。
4. MSIX 打包与签名流程可复现。无生产签名证书时可生成用于本地验证的包与签名说明，但明确标注开发信任条件，不能声称可直接面向所有用户分发。不自动导入证书、使用私人签名密钥、上传商店或发布。
5. 应用始终手动更新：不实现后台检查/下载/更新器，不提供 Agent 自动更新。若 MSIX 分发机制存在平台管理行为，说明与应用行为的区别；不添加带自动检查策略的 App Installer 发布配置。
6. 两种分发模式数据默认隔离，不悄悄互读/迁移。提供各自数据目录、备份/手动替换升级和手动卸载说明；正式导入导出到后续版本实现，不能提前伪装提供。
7. 在干净 Windows 环境分别验证 ZIP 和安装后的 MSIX：正常新建页、四种 Shell、中文输入、透明/性能模式、Profile、保存/恢复、MCP、UAC、关闭及手动升级后的配置兼容。签名/权限/系统限制有阻塞时列明缺项，不能宣告发布完成。

### 首版完成条件与测量口径

- 冷启动测量到新建页可交互；创建终端测量到可交互会话，分别报告，不能把延迟加载时间藏掉。标签切换不应重启进程或重建整份回滚。
- 持续输出至少记录吞吐、队列/回滚占用、UI 输入响应和进程资源。20 标签中区分活动与后台，极光活动/关闭/性能模式分别比较。记录 CPU、内存、OS 构建、DPI、Shell、样本条件与时长。
- 资源稳定性用重复会话循环和持续输出观察增长/回收，不能从一次截图推断没有泄漏。列出有限缓存的预期保留与异常持续增长。
- 优化不丢 VT 字节、不损坏 Unicode/IME、不跳过授权/配置落盘保障。性能改善必须有可比条件，未实测不填百分比。
- 所有关键功能在打包前通过一次，安装/解压后的关键路径再复验。存在包身份、路径重定向、原生 DLL、提权或 MCP 入口差异时，分别记录。
- MSIX 签名身份和证书不可伪造；开发签名与正式可分发签名分开说明。不修改用户信任存储或发布商店。必要安装验证仅在明确的隔离测试环境执行并按环境权限处理。
- ZIP 默认 self-contained win-x64；使用该默认前核实运行时分发许可和已有项目约束。MSIX 的运行时依赖策略要明确且可复现。无需求不启用 trimming、AOT、单文件。
- 应用始终手动更新，不做后台检查/下载，不更新 Agent CLI；不添加自动检查型 App Installer 配置。平台管理的更新机制与应用自身行为如实区分。
- 发布只生成本地可审阅产物，不自动部署、推送或上传。缺少签名/测试环境时仍完成可完成的打包准备，并标明阻塞，不把未验证包称作发布完成。
