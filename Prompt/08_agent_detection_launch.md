# ArkTerminal · Prompt 08：Agent CLI 检测与快速启动

版本：2026-10-30 · 原始十阶段增强版

使用方式：将本文件全文交给实施 Agent，并明确要求执行本阶段。本文件已包含必要约束与验收，可独立作为阶段 Prompt；运行依赖仍需前序阶段提供。当前交付内容是规划文档。

## 一、任务梗概

识别七类 Agent CLI、允许 JSON 声明式扩展，并将检测结果转换成可编辑的启动配方。优先 PowerShell 7，保留 PowerShell 5 回退，首次检测不启动任务。

## 二、前置条件与任务范围

**前置条件：**Profile、终端启动、标题/状态和 Shell 集成边界稳定；阶段 4 新建页与命令面板具备注册入口。

**本阶段包含：**内置候选适配器、有限扫描/探测/缓存、JSON schema 与启用流程、路径覆盖、模型/权限/参数配方、状态展示与 pwsh 回退。

**阶段边界：**工作区共享资料、已确认摘要恢复任务、Agent 并排对比在后续版本；本阶段不引入完整插件系统或 CLI 自动更新。

## 三、必须遵守的工程约束

你是 ArkTerminal 的实施 Agent。收到本文件及明确的实施指令后，只执行本阶段；本文件本身不代表用户已要求开始编写应用。

以下是贯穿首版的最终约束；尚未轮到的功能按本阶段范围预留，不提前扩张实现。

- 产品是 Shell 与 Agent 并重的 Windows 10/11 x64 原生 WPF 工作台。保留 `net10.0-windows`、ConPTY 和原生渲染路线；不使用 WebView2/xterm.js，不引入大型 UI 框架。最低 Windows 构建号须以实际依赖和能力验证为准。
- 先读仓库 `AGENTS.md`、解决方案、相关源码和已有阶段交接。原材料描述仓库接近空白，实施时重新核实，保留用户已有改动和稳定公共契约。不要仅因文件名不同就复制一套同职能服务。
- 每个 Session 独立拥有进程、I/O、缓冲和取消源；View 负责显示与输入。UI 线程不做扫描、进程探测、输出解析或阻塞 I/O；队列、缓存、日志、回滚均有上限和释放路径。
- 首版同时支持标准数据目录与便携模式；所有文件访问经统一数据根服务，配置原子写入。标准/MSIX/便携模式的数据默认隔离，不静默迁移或降级覆盖高版本配置。
- 正常启动显示新建页，由用户选择项目或 Agent；崩溃恢复只恢复待确认配置草稿和未启动布局。专注模式保留标签栏。完整工作区、多窗口、分屏和 Quake 在后续版本实现。
- 不自动运行检测到的 Agent，不修改用户 Agent 全局配置，不收集遥测或自动上传正文。应用命令历史和按会话输出保存默认关闭；MCP 首版只读。模型建议的生成、投递与实际执行分别处理。

文中的默认上限与时长是实施建议，不是用户逐项指定的硬指标。实现为集中可调整配置；如需调整，在交付中说明原因和实际值，不能悄悄放宽用户已确认的权限与数据边界。

## 四、任务要求

1. 为 codex、deepseek harness、claude code、kimi code、opencode、antigravity、codebuddy 建立显示名与候选表。逐项核实可执行名/版本参数及是否确有交互 CLI；不能把产品名直接当命令。无法确认时显示未确认或不支持，而非安装成功。
2. 检测 PATH 与有限常见目录，不扫描全盘；异步、有取消、并发上限、单探测超时/输出上限。建议默认并发 2、单探测 3 秒、输出 64 KiB，可调整。启动轻量验证缓存，版本探测按需/刷新执行。
3. 探测会运行第三方可执行程序，只运行确认的版本探测参数，不安装、不登录、不更新。自定义 JSON 文件先校验/启用，不因出现在目录就自动执行它声明的命令。
4. 优先 pwsh.exe，缺少才用 powershell.exe 包装 Agent 启动。区分可执行文件、cmd 包装器与 PowerShell 脚本；用经过验证的参数/脚本调用方式处理路径、引号、反引号、分号及 $ 字符，不靠字符串拼接。
5. 为用户生成可编辑 Profile/配方：模型、权限模式、目录、参数、Shell 后端；仅保存已验证的适配器参数，不假定各 CLI 有同名开关。敏感令牌不入配方，启动继承必要环境但不在界面/日志泄露。
6. JSON schema 包含稳定 ID、名称、可执行候选、版本命令、参数模板、字段/变量白名单及支持的状态信号，限制大小/递归/模板展开。不支持任意 C#、JavaScript、PowerShell 插件钩子；启动参数本身可执行外部程序，启用前展示实际命令。
7. 结果区分已发现且验证、已发现未验证、未安装、超时、配置无效/不支持，展示路径、版本与原因。无 pwsh 的回退明确可见，不产生启动失败循环。
8. Agent 与普通终端复用同一内核；可靠信号可展示执行/等待/失败/耗时，无信号就未知，不解析任意一句输出猜测。

### 检测与参数设计

| 适配器字段 | 必须表达的语义 |
| --- | --- |
| id / displayName | 稳定唯一标识与显示名，重复 ID 给出冲突 |
| executableCandidates / overridePath | 候选及用户修正路径，产品名不等于可执行名 |
| versionProbe | 已核实的命令/参数、超时和输出上限；退出结果不等于交互能力已验证 |
| launchTemplate | 结构化参数和允许变量，模型/权限字段只映射实际 CLI 支持选项 |
| capabilities / statusSignals | 真实可用的文本输入、resume/状态等能力；不支持就明确禁用 |

执行检测前核对候选来源。内置适配器可以运行已核实的版本命令；新导入 JSON 必须先校验/启用，不能看到一个文件就执行其中任意程序。默认探测并发 2、3 秒超时、64 KiB 输出，超时取消需回收探测进程。

PATH、常见目录与用户路径三个来源可追踪，优先级明确。缓存记录来源/路径与探测时间；启动轻量校验，不每次遍历大量目录。路径存在但无法运行与未安装不是同一状态。

可执行文件、.cmd 包装器、PowerShell 脚本各有调用语义；要分别验证引号、分号、美元符号等特殊参数，不能仅靠 ArgumentList 宣称整条嵌套 Shell 路径都安全。配方中的运行权限是 CLI 参数配置，不应绕过 OS 的 UAC 或 CLI 自身授权。

所有条目记录实际状态和证据；“未验证”必须说明缺少的条件。适用平台限制需要单列，不能用禁用界面冒充完整实现。

| 编号 | 场景 | 验证操作 | 通过标准 |
| --- | --- | --- | --- |
| 08-AC01 | 七类状态 | 逐项已安装/未安装/无法确认/超时条件 | 每类有明确状态和原因，不能把猜测的命令当成功。 |
| 08-AC02 | 首次启动 | 启动应用并等待异步检测 | 新建页保持可用，不登录/安装/更新或自动运行 Agent 任务。 |
