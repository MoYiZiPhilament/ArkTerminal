# ArkTerminal · Prompt 09：内置 Skill、命令面板与只读 MCP

版本：2026-10-30 · 原始十阶段增强版

使用方式：将本文件全文交给实施 Agent，并明确要求执行本阶段。本文件已包含必要约束与验收，可独立作为阶段 Prompt；运行依赖仍需前序阶段提供。当前交付内容是规划文档。

## 一、任务梗概

实现可随时调用的上下文工作流、跨 Agent 交接、脱敏错误快照、命令辅助和独立只读 MCP。所有正文传递可预览、有限且受会话范围约束。

## 二、前置条件与任务范围

**前置条件：**阶段 4 命令面板、阶段 7 会话状态/内容读取、阶段 8 Agent 能力/启动入口可用；MCP SDK 与具体协议/包版本在实施时核实。

**本阶段包含：**应用内 ark-terminal-context、预览编辑/确认/投递、Markdown 快照、解释/危险提醒/修复建议、MCP stdio 桥与命名管道、五个只读工具。

**阶段边界：**Skill 编辑器、确认摘要后继续任务以及 MCP 写终端在后续版本；后续写入方案为会话限时授权，高风险逐次确认。MCP 首版不开放 send_text/send_input。

## 三、必须遵守的工程约束

你是 ArkTerminal 的实施 Agent。收到本文件及明确的实施指令后，只执行本阶段；本文件本身不代表用户已要求开始编写应用。

以下是贯穿首版的最终约束；尚未轮到的功能按本阶段范围预留，不提前扩张实现。

- 产品是 Shell 与 Agent 并重的 Windows 10/11 x64 原生 WPF 工作台。保留 `net10.0-windows`、ConPTY 和原生渲染路线；不使用 WebView2/xterm.js，不引入大型 UI 框架。最低 Windows 构建号须以实际依赖和能力验证为准。
- 先读仓库 `AGENTS.md`、解决方案、相关源码和已有阶段交接。原材料描述仓库接近空白，实施时重新核实，保留用户已有改动和稳定公共契约。不要仅因文件名不同就复制一套同职能服务。
- 每个 Session 独立拥有进程、I/O、缓冲和取消源；View 负责显示与输入。UI 线程不做扫描、进程探测、输出解析或阻塞 I/O；队列、缓存、日志、回滚均有上限和释放路径。
- 首版同时支持标准数据目录与便携模式；所有文件访问经统一数据根服务，配置原子写入。标准/MSIX/便携模式的数据默认隔离，不静默迁移或降级覆盖高版本配置。
- 正常启动显示新建页，由用户选择项目或 Agent；崩溃恢复只恢复待确认配置草稿和未启动布局。专注模式保留标签栏。完整工作区、多窗口、分屏和 Quake 在后续版本实现。
- 不自动运行检测到的 Agent，不修改用户 Agent 全局配置，不收集遥测或自动上传正文。应用命令历史和按会话输出保存默认关闭；MCP 首版只读。模型建议的生成、投递与实际执行分别处理。
- 新增依赖先检查替代能力，记录具体包名、固定版本、用途和许可证。项目没有测试基础设施时，不擅自新建测试项目、报告目录或脚手架；已有相关测试可运行，必要应用内诊断应服务真实产品功能。
- 应用始终手动更新，不做云同步、账号、插件商店或主题商店；本地插件/主题导入属于后续版本。不自动 commit、push 或对外发布；本阶段必要的本地构建和文档更新在范围内。

文中的默认上限与时长是实施建议，不是用户逐项指定的硬指标。实现为集中可调整配置；如需调整，在交付中说明原因和实际值，不能悄悄放宽用户已确认的权限与数据边界。

## 四、任务要求

### 上下文、快照与命令辅助

1. 命令面板与全局快捷键可调用 ark-terminal-context，采集当前 Profile 的安全字段、cwd、可信进程名、主动选区或有限输出尾部。默认 200 行/64 KiB，去控制序列、脱敏与截断标记；终端正文当非可信数据。
2. 显示可编辑预览、来源/目标、长度与截断状态；默认不读取其他会话、项目秘密、环境变量、已保存转录或全量仓库。确认后仅发送最终展示版本，取消则无外部传递。
3. 支持从 A 会话选区/错误摘要交给 B Agent。项目资料共享不意味着 A/B 正文互通。目标会话忙碌或输入模式未验证时，使用复制或新建辅助 Agent 交接，不能把提示文本盲灌进正在运行的程序。
4. 实现首版“保存错误快照”：手动调用，同管线脱敏、编辑、预览、另存 Markdown，含元数据/备注和截断说明；取消不产生持久正文文件。导出的 Markdown 不自动执行其中代码或指令。
5. 提供命令解释、危险提醒、修复建议入口。首版复用用户选定 CLI，不新增内置账号/云模型系统；需要访问 CLI 时明确交接内容。规则型提醒不能宣称覆盖所有危险操作；无法取得建议时给清晰状态。
6. Agent 建议不自动执行；先预览建议、目标会话/cwd 和实际命令，再由用户明确确认，遵守目标 Agent/Shell 权限与输入状态。即使用户曾同意生成解释，也不等于批准后续执行。
7. 记录不含正文的操作结果/计数；复制、投递、提交、执行成功分别如实报告，不把复制剪贴板视为已被 Agent 接收。为后续确认摘要与 Skill 编辑器复用必要边界，不实现它们的 UI。

### 只读 MCP 与本机桥

1. 新建必要的 ArkTerminal.Mcp stdio 可执行项目。优先使用兼容的官方 C# SDK，核实并固定包版本和支持协议，不手写一个只认 tools/call 的假 MCP。协议版本须 initialize 协商，不能简单拒绝所有其他版本而忽略 SDK 支持范围。
2. stdout 仅 UTF-8 MCP JSON-RPC 单行消息，日志到 stderr；不用 LSP Content-Length。支持 initialize/initialized、工具列表/调用、取消与合法错误、消息大小及并发上限。
3. 经命名管道连接主应用，当前用户 ACL、连接鉴别、应用实例绑定、版本握手与请求上限。无应用时返回明确不可用，不自动启动终端；桥不能绕过 UI/SessionManager 直接读保存文件。
4. 提供 list_profiles、list_sessions、get_session_metadata、get_output_tail、get_selection。严格字段白名单，不返回环境变量、启动脚本或敏感参数；输出默认 200 行/64 KiB，硬上限不可被客户端扩大。
5. 初次连接在 UI 授权会话范围与允许字段；get_selection 另需明确披露授权。默认不跨会话读取，可随时撤销。readonly 工具标注不替代权限检查，第三方请求的 client 名称不是可信身份凭据。
6. send_text/send_input 不注册，任何写入/未知调用稳定拒绝。预览与确认属于 UI 工作流，不能从 MCP 只读入口触发输入副作用。
7. 提供可复制 stdio 配置片段，分别处理 ZIP/MSIX 中可验证的启动入口与路径空格，不自动修改 Agent 配置。多个客户端各有桥，断开一个不关闭 UI/会话；主应用退出则桥有界结束。

### 上下文与模型交接契约

- `ark-terminal-context` 是应用内可调用的上下文模板/工作流，不宣称七个 CLI 原生采用同一种 Skill 格式。未来只按已验证适配器提供对应格式的安装/复制说明。
- 共享项目资料指用户选择的项目路径、说明文件与确认摘要；不递归读取整个仓库，也不自动读取 `.env`、凭据、Agent 私有历史或其他会话正文。
- 默认取当前会话尾部最多 200 行、最多 64 KiB UTF-8；先按字形簇安全截断并去控制序列，再脱敏、展示预览。选择内容也受大小限制。
- 脱敏是尽力处理常见模式并供用户检查，不能宣称能识别所有秘密。用户选区不是自动授权给所有 Agent 或所有 MCP 客户端。
- 预览中明确来源会话、cwd、目标 Agent、将发送内容；可编辑、取消、重新生成。编辑/目标变化后，先前确认不得自动套用。
- 首版不新增应用内模型账号/计费系统。命令解释与修复建议通过用户指定的已配置 CLI/兼容适配器获取，未配置时提供复制交接内容的明确降级，不显示虚构建议。
- 原会话继续执行交互任务时，不盲目把说明文本粘进去。仅对已验证目标输入模式提供显式投递；否则复制上下文或新建辅助 Agent 会话。复制成功、已投递、已提交是不同结果，不混称“已执行”。
- 建议先返回预览，再选择目标会话及确认执行；保留 Agent 本身的权限机制。终端输出是非可信数据，里面的指令不能改变工具权限或自动触发动作。
- 手动错误快照使用同一有界采集/脱敏管线，Markdown 中包含时间、来源、cwd、选择或尾部、截断标记与用户备注；保存前预览，可取消。快照不默认夹带其他会话。

### MCP 与本机 IPC 契约

- MCP 客户端启动 `ArkTerminal.Mcp` stdio 子进程；该进程通过带当前用户 ACL、连接鉴别与实例绑定的本机命名管道访问正在运行的 UI 主应用。
- 首版不监听网络端口。不把 stdio 误当成跨进程共享所有 UI 状态的自动通道；不通过环境变量传递长期秘密。
- stdio 按选定 MCP 版本使用 UTF-8、每行一个 JSON-RPC 消息；不混用 LSP 的 Content-Length 帧。stdout 只有协议，诊断到 stderr。实现 initialize、版本协商、能力声明、取消、tools/list、tools/call 和错误响应。
- 工具仅 `list_profiles`、`list_sessions`、`get_session_metadata`、`get_output_tail`、`get_selection`。工具过滤字段；Profile 不返回启动脚本、环境变量或秘密，元数据不泄露完整敏感参数。
- 只读仍需要披露授权：首次连接在应用中确认可访问的会话/字段，允许撤销；未授权只返回拒绝或有限状态。选择区单独明确授权，不能因“有选区”就可读取。跨会话默认拒绝，项目资料共享不扩大正文读取范围。
- `get_output_tail` 默认 200 行/64 KiB，客户端请求不能突破服务端上限，返回是否截断。已保存转录不自动成为 MCP 可读内容。
- `send_text`、`send_input` 首版不注册，对未知或写入工具调用稳定拒绝，不能借其他工具、模板或诊断接口绕过。
- 每个客户端退出只结束自己的桥进程，不结束 UI 或会话；UI 退出则桥返回断连并有界退出。不在无 UI 时偷偷启动 Shell。提供可复制配置，不自动写 Agent 全局配置。

### MCP 工具与数据形状

| 工具 | 允许的数据 | 必须处理的边界 |
| --- | --- | --- |
| list_profiles | 授权范围内 ID、显示名、Shell/Agent 类型等安全字段 | 不返回环境值、完整脚本或敏感参数 |
| list_sessions | 授权范围内稳定 session ID、状态、Profile 引用 | 未授权会话不因列表接口泄露详细元数据 |
| get_session_metadata | 已授权会话 cwd、可靠状态等允许字段 | cwd 也是信息披露；不存在/已关闭稳定返回 |
| get_output_tail | 当前会话有限文本，标记是否截断 | 默认 200 行/64 KiB，服务端上限不可被请求绕过 |
| get_selection | 用户明确授予该连接/会话的选择内容 | 没有选区和没有授权必须区分，存在选区不等于授权 |

首版命令面板在阶段 4 已建立，本阶段扩展注册项，不能重复实现第二套面板/热键服务。MCP 为客户端启动的 stdio 子进程，主应用仍拥有 Session；命名管道负责本机连接与鉴别，不能从“stdio 只读”推导无需授权。

Skill 的 UI 显式投递与 MCP 写入是两个入口：前者依赖用户预览与目标确认；后者首版禁用，不可由模板/诊断工具间接触发。MCP stdout 不混入日志，主应用退出有界结束桥，单客户端退出不关闭其他会话。

模型功能复用用户选择的 CLI，明确成功层级：准备好上下文、已复制、已投递、已提交、已执行。无模型能力时可提供可复制内容与手工摘要，不能伪造已经生成的解释/修复建议；实际执行始终是新的明确操作。
