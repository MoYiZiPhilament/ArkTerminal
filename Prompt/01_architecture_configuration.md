# ArkTerminal · Prompt 01：架构基线与配置契约

版本：2026-10-30 · 原始十阶段增强版

使用方式：将本文件全文交给实施 Agent，并明确要求执行本阶段。本文件已包含必要约束与验收，可独立作为阶段 Prompt；运行依赖仍需前序阶段提供。当前交付内容是规划文档。

## 一、任务梗概

建立可持续扩展的三层项目结构、数据目录和配置契约，让后续终端、设置、Agent 与恢复能力共享一致的底层规则。首版便携模式从本阶段纳入，避免发布时再迁移散落路径。

## 二、前置条件与任务范围

**前置条件：**现有 WPF 项目可被识别；核实实际目标框架、启动入口、解决方案与已安装 SDK。不存在相关基础模块时再创建；不得假定原材料的“空白项目”仍然成立。

**本阶段包含：**项目引用、配置模型/版本/校验、标准与便携数据根、原子存储、草稿恢复底层、会话边界、启动退出组合根。

**阶段边界：**本阶段不创建完整终端、设置页、Agent 检测器或插件框架。工作区只保留必要关联边界，MCP/提权辅助器到阶段 9/7 再建。

## 三、必须遵守的工程约束

你是 ArkTerminal 的实施 Agent。收到本文件及明确的实施指令后，只执行本阶段；本文件本身不代表用户已要求开始编写应用。

以下是贯穿首版的最终约束；尚未轮到的功能按本阶段范围预留，不提前扩张实现。

- 产品是 Shell 与 Agent 并重的 Windows 10/11 x64 原生 WPF 工作台。保留 `net10.0-windows`、ConPTY 和原生渲染路线；不使用 WebView2/xterm.js，不引入大型 UI 框架。最低 Windows 构建号须以实际依赖和能力验证为准。
- 先读仓库 `AGENTS.md`、解决方案、相关源码和已有阶段交接。原材料描述仓库接近空白，实施时重新核实，保留用户已有改动和稳定公共契约。不要仅因文件名不同就复制一套同职能服务。
- 每个 Session 独立拥有进程、I/O、缓冲和取消源；View 负责显示与输入。UI 线程不做扫描、进程探测、输出解析或阻塞 I/O；队列、缓存、日志、回滚均有上限和释放路径。
- 首版同时支持标准数据目录与便携模式；所有文件访问经统一数据根服务，配置原子写入。标准/MSIX/便携模式的数据默认隔离，不静默迁移或降级覆盖高版本配置。
- 正常启动显示新建页，由用户选择项目或 Agent；崩溃恢复只恢复待确认配置草稿和未启动布局。专注模式保留标签栏。完整工作区、多窗口、分屏和 Quake 在后续版本实现。
- 不自动运行检测到的 Agent，不修改用户 Agent 全局配置，不收集遥测或自动上传正文。应用命令历史和按会话输出保存默认关闭；MCP 首版只读。模型建议的生成、投递与实际执行分别处理。
- 新增依赖先检查替代能力，记录具体包名、固定版本、用途和许可证。项目没有测试基础设施时，不擅自新建测试项目、报告目录或脚手架；已有相关测试可运行，必要应用内诊断应服务真实产品功能。
- 应用始终手动更新，不做云同步、账号、插件商店或主题商店；本地插件/主题导入属于后续版本。不自动 commit、push 或对外发布；本阶段必要的本地构建和文档更新在范围内。

文中的默认上限与时长是实施建议，不是用户逐项指定的硬指标。实现为集中可调整配置；如需调整，在交付中说明原因和实际值，不能悄悄放宽用户已确认的权限与数据边界。

## 四、任务要求

1. 核实仓库基线，建立/复用 ArkTerminal、Core、Terminal，保持启动项目为 WPF。MCP 和提权辅助器项目到对应阶段再建。
2. 建立 AppSettings、AppearanceSettings、TerminalProfile、AgentDefinition、AgentDetectionResult、启动配方、历史/转录策略、RecoveryState 等必要模型，配置含 schemaVersion。未来工作区仅预留 ID/关联边界，不先实现完整功能。
3. 定义数据根、配置/Profile 服务、Session/Manager、Agent 检测/启动、屏幕快照、输入、渲染、上下文采集所需的最小边界；避免包含全套未来插件接口。
4. TerminalProfile 包含名称、图标、可执行文件与参数、启动后执行、cwd 与 {{home}}、KEY=VALUE 环境变量、管理员模式、Shell 集成、字体/配色/回滚和 Agent 配方。区分 Shell 脚本、进程参数和会话元数据。
5. 实现标准数据根与 portable.flag/--portable 规则，预留 MSIX 能力探测。可写性检查、原子保存、迁移、损坏备份、并发保存与高版本保护全部接入。
6. 独立保存设置草稿、未启动的标签布局和异常退出标记。正式保存、取消预览、草稿恢复和正常关闭状态互不污染，不保存活进程内存或恢复命令。
7. 组合根接入取消/异步释放；在首版单窗口范围内控制重复启动对配置的并发写入，IPC 为未来多窗口留下清晰边界。

### 数据根、便携与恢复契约

推荐实施默认值属于本规划的补充，可在实现中作为可配置常量，不再要求用户逐项确认：

1. 标准未打包运行默认 `%APPDATA%/ArkTerminal`。所有路径来自统一 `IAppDataPaths`，覆盖配置、草稿、恢复、背景图、诊断、适配器、历史与会话保存。
2. ZIP 默认包含 `portable.flag`，显式 `--portable` 也可启用；数据写入程序目录下 `data/`，内部资源使用相对引用。未打包且未开启便携模式时使用标准目录。
3. MSIX 使用可写的用户数据根，具体路径结合所选包模型与重定向行为验证；不得写安装目录。应用内显示实际数据目录。MSIX 中请求便携模式时说明不适用，不偷偷写入另一目录。
4. 便携目录无写权限、只读介质或磁盘满时显示可操作错误，不静默回退 APPDATA，也不以管理员权限掩盖问题。
5. JSON 包含 schemaVersion；校验、迁移、原子替换、损坏备份与并发写入控制统一实现。高版本 schema 不应被旧版本静默降级覆盖。
6. 设置即时预览作用于临时状态；保存才更新正式配置。草稿自动保存到独立恢复文件，取消时撤回预览并删除对应草稿，不污染正式设置。
7. 正常启动始终显示新建页。检测到异常结束时，在新建页提供恢复/丢弃入口；恢复草稿进入待确认编辑态，恢复标签布局只产生未启动的占位卡。用户明确启动后才重建新进程。
8. 正常关闭前已有的未保存设置由保存/放弃流程处理，不能把它伪装为崩溃恢复。新建页的最近项目记录不等于完整工作区功能。

### 建议交付的最小契约

| 边界 | 本阶段应明确的责任 |
| --- | --- |
| IAppDataPaths | 当前运行模式、实际数据根、配置/草稿/背景/日志等路径；不得由各模块自行拼 APPDATA |
| 配置服务 | 加载、校验、迁移、原子保存、损坏备份、版本冲突结果；错误可供 UI 展示 |
| Profile 服务 | 稳定 ID、默认项、增删改校验；运行时秘密不进入可导出的启动配方 |
| Session / Manager | 创建、状态、resize、输入、关闭、异步释放与事件边界；此阶段不伪造实现 |
| RecoveryState | 异常退出标记、草稿版本、标签顺序/配置引用；不保存恢复命令或活进程 |

命名以仓库现有约定为准。草稿与正式配置分开保存；先确保同目录临时文件写入及替换策略可用，再实现损坏恢复。备份数量必须有上限，不能每次失败无限复制。JSON 不允许含真实凭据的默认示例。

2. 先完成最小闭环，再接入用户可见入口，最后处理取消、异常、资源释放与恢复。已有稳定功能优先复用。
3. 若前置阶段有局部缺陷，修复本阶段必要的最小范围并说明；若核心能力完全缺失，明确依赖缺口，不以模拟成功或空实现替代。
4. 每阶段结束运行 `dotnet build ArkTerminal.sln`。实际解决方案名称不同则使用核实后的路径，并记录真实命令与退出结果；Release 要求以各阶段验收为准。
5. 逐项执行下列验收并记录“通过 / 失败 / 未验证”。缺少 Windows、交互桌面、具体 Shell、设备或证书时如实说明；编译成功不等于中文 IME、UAC 或桌面材质实测通过。
6. 保持本阶段结束时可构建、可启动、可回退。不自动执行下一阶段，不通过新增视觉功能绕过阶段 2/3 的质量问题。
